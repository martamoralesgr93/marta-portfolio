El Problema
Años de deuda de diseño sin estándares comunes: interfaces sobrecargadas y bloqueos graves de accesibilidad (contraste < 3:1).
Mi Rol
Única responsable del diseño del sistema, la accesibilidad y la adopción de tokens con frontend.
Qué Hice
  • Auditoría heurística y triage de deuda
  • Tokens y paleta conforme WCAG AA
  • UI Kit en Figma con variantes y estados
Resultado
Cumplimiento WCAG AA en todos los componentes interactivos y reducción del time-to-market mediante componentes modulares.

01 · Diagnóstico

Años de deuda de diseño
y contraste por debajo de 3:1.

Campus, calendario, matrícula, login y bolsa de empleo habían crecido cada uno por su lado: sin tokens, sin nomenclatura y sin guía de accesibilidad.

Fase 1 · Auditoría & Triage

Auditoría UX y triage de problemas

Insight Problemas sistémicos, no estéticos: contraste < 3:1, affordance rota, flujos inconsistentes.
Hipótesis Si establecemos los estándares antes que la UI, los componentes serán correctos por construcción.
Decisión Invertir las primeras semanas en auditar, argumentando a dirección la falta de UI visible inmediata.
Fase 2 · Estándares & Contraste

Definición de estilos y accesibilidad (WCAG)

Innegociable en EdTech: paleta con contraste AA, tipografía legible y componentes base estandarizados.

MI PLAYBOOK · FIGMA + CLAUDE (MCP) — Los 4 flujos con los que construí esta recreación — The 4 workflows I used to build this recreation
1.

Diseñar con el sistema

Claude conectado a Figma por MCP diseña usando mis variables y componentes reales — nada hardcodeado. El prompt clave: «usa las variables y los componentes que ya tengo en el archivo».

Claude connected to Figma via MCP designs using my real variables and components — nothing hardcoded. The key prompt: "use the variables and components already in the file".

2.

Auditar y corregir

Puntúa el sistema de 0 a 100 por categoría —naming, tokens, accesibilidad, consistencia, cobertura—, localiza la capa exacta del fallo y corrige. Pero dejó variables sin ejecutar y componentes desconectados de su story: la jerarquía real hubo que forzarla a mano. La IA aplica el criterio que le des; si está incompleto, produce un sistema que puntúa bien y falla igual.

It scores the system 0–100 per category —naming, tokens, accessibility, consistency, coverage—, pinpoints the faulty layer and fixes it. But it left variables unexecuted and components disconnected from their story: real hierarchy had to be forced by hand. AI applies the judgement you give it; if that's incomplete, it produces a system that scores high and still fails.

3.

Prototipar en minutos

La IA genera la pantalla en código, la importo a Figma con HTML to Design y vinculo mis tokens. Bases de logins, checkouts y landings listas en minutos, no en días.

AI generates the screen as code, I import it into Figma with HTML to Design and bind my tokens. Login, checkout and landing foundations ready in minutes, not days.

4.

Vibe coding: de Figma a producto

Paso los diseños a Claude Code para que genere sus propios tokens y componentes en código, y las pantallas futuras mantengan la cohesión. Resultado real: los 57 tokens publicados en GitHub ↗

I hand the designs to Claude Code asking it to interpret the design and generate its own design tokens and components in code. Future screens keep the system's cohesion. Real output: the 57 tokens published on GitHub ↗

La IA no me sustituye: me multiplica. Sin criterio produce productos genéricos. Aquí: mismo sistema, mismo rigor WCAG, una fracción del tiempo.AI doesn't replace me: it multiplies me. Without judgement it produces generic products. Here: same system, same WCAG rigour, a fraction of the time.

Aprendizajes

Lo que construir un sistema
desde cero enseña

La adopción es el entregable

El design system no es el entregable. La adopción sí. El objetivo era que desarrollo lo usara como referencia única, no recibir un Figma.

Estructura antes que estética

Empezar por estructura cambia el resultado. La baja fidelidad evita tapar problemas de jerarquía con recursos visuales.

WCAG AA

La accesibilidad como palanca

La accesibilidad es palanca, no límite. Redefinir la paleta para cumplir AA dio colores más versátiles y legibles en cualquier contexto.

Diseñar para el equipo interno

Diseñar sistemas es diseñar para el equipo. Si la librería incomoda en Figma o los tokens no son lógicos en código, el sistema muere.
